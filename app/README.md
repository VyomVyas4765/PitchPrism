# Mobile starter · Dev 1

Flutter entry point for entrepreneur phone sign-in and facilitator password sign-in. Android is the product target (PRD Q-06); an iOS project exists for team device testing (see below). API sessions use `flutter_secure_storage`. Actual pitching, offline intake, language selection and processing/sharing consent workflows remain in the duty brief.

```bash
cd app
flutter pub get
flutter run
```

Default API: `http://10.0.2.2:4000/api/v1` for the Android emulator. For a physical device, pass `--dart-define=API_BASE_URL=http://YOUR_LAN_IP:4000/api/v1`. Use HTTPS for release environments; cleartext traffic is enabled only in the debug manifest. Release signing is a deployment duty; the generated Android project still uses a debug signing configuration.

## Firebase phone setup

Register Android package `in.pitchprism.pitchprism_app`, register the signing SHA-1/SHA-256 fingerprints, and enable Firebase's Phone provider. In the repository root create ignored `local/mobile-config.json` with your Firebase Android settings:

```json
{
  "FIREBASE_PROJECT_ID": "your-project-id",
  "FIREBASE_API_KEY": "your-android-api-key",
  "FIREBASE_APP_ID": "your-android-app-id",
  "FIREBASE_MESSAGING_SENDER_ID": "your-sender-id"
}
```

From `app/`, run `flutter run --dart-define-from-file=../local/mobile-config.json`. The app initializes Firebase explicitly from those options. The backend needs the same project ID and Application Default Credentials (`GOOGLE_APPLICATION_CREDENTIALS` points to a private service-account file). No SMS can be sent until the project is configured. Use Firebase's configured test phone numbers for development; there is no hard-coded OTP or authentication bypass.

## iOS test build (needs a Mac)

iOS apps can only be built and signed with Xcode on macOS. The `ios/` project (bundle ID `in.pitchprism.pitchprismApp`, iOS 15+) is committed; files with machine paths are regenerated by `flutter pub get`.

1. On the Mac: install Xcode from the App Store, open it once to finish setup, then install Flutter 3.47+ and check `flutter doctor`.
2. `git pull` the branch, then `cd app && flutter pub get`.
3. On the iPhone (iOS 16+): Settings → Privacy & Security → Developer Mode → on. Connect it by USB and tap Trust.
4. `open ios/Runner.xcworkspace`. Select **Runner** → **Signing & Capabilities** → Team → add your Apple ID (a free Personal Team works). If Xcode says the bundle ID is unavailable, change it locally (for example append your name) and do not commit that change.
5. Start the API on a computer on the same Wi-Fi (`pnpm dev` from the repository root) and find that computer's LAN IP. On Windows, allow Node through the firewall for port 4000.
6. From `app/`: `flutter run --release --dart-define=API_BASE_URL=http://YOUR_LAN_IP:4000/api/v1`. Release mode stays installed and opens without the Mac.
7. First launch: on the iPhone, Settings → General → VPN & Device Management → trust your developer certificate. Allow the Local Network prompt so the app can reach the API.

Plain HTTP is allowed only for local-network hosts (LAN IPs and `*.local`); internet hosts need HTTPS. Free Personal Team installs expire after 7 days; run step 6 again to refresh. An `.ipa` file for TestFlight or ad-hoc sharing needs a paid Apple Developer Program membership and `flutter build ipa`.

**Sign-in on iOS.** Facilitator email/password sign-in works with the steps above. Entrepreneur phone OTP is not configured for iOS yet: register an iOS app with this bundle ID in the team's Firebase project, add its reCAPTCHA URL scheme (the encoded app ID) to `ios/Runner/Info.plist`, optionally upload an APNs key (paid account) for silent verification, and run with an iOS variant of `mobile-config.json` whose `FIREBASE_APP_ID` is the iOS app ID.

See [Firebase Flutter phone authentication](https://firebase.google.com/docs/auth/flutter/phone-auth) and [backend token verification](https://firebase.google.com/docs/auth/admin/verify-id-tokens). Device/SMS validation requires the team's Firebase configuration and is not covered by backend adapter tests.
