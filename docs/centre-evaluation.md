# Centre evaluation integration

The Dev 2 evaluation entry point consumes **redacted, extracted evidence**, not a raw PDF. Dev 1's upload/extraction stage must store the immutable original privately, then produce the `CentreExtractedInput` contract in `packages/contracts/schemas/centre-extracted-input.json`. The submission must already belong to a centre. The planned business site in `context.plannedBusinessLocation` is authoritative when phone GPS or the applicant's home differs.

Each answer has one of `answered`, `missing`, `not_asked`, `irrelevant`, or `unreadable` and cites segment IDs. Profile skills/experience may be represented as `profile` segments and cited fields. A profile-confirmed business site must cite its own profile segment; it replaces a conflicting PDF location for scoring and is flagged for assessor review. PDF segments carry page and, when available, bounding box, original-language text, English translation, read confidence, and struck/superseded state. The extractor redacts name, phone, email, exact address, and social category before this handoff. The API and worker reject detected phone/email patterns and invalid citations; this is defense in depth, not a substitute for Dev 1's redaction and private original storage.

Centre assessor and cohort lead sessions may submit an extracted input to `POST /api/v1/centre/submissions/:id/assessment`. The route rechecks the owning centre, uses the server's provisional rubric, invokes the local-only Python scorer, stores both model runs and citations, and archives any earlier undecided evaluation. `GET /api/v1/centre/queue` and `/submissions/:id/card` serve the web review screen. `POST /submissions/:id/decision` records Shortlist, Not yet, or More information; override reasons are required when the assessor departs from the suggested pathway or shortlists a low-information idea. `PUT /submissions/:id/feedback` saves an English draft with `awaiting_translation_and_delivery` status. The applicant-facing submission status reflects the human decision.

With no approved `LOCAL_LLM_MODEL`, the CLI returns `pending_model` and no potential score. The installed `llama3.2:latest` completed one synthetic format run, but gave a very high score to generic synthetic text; it is **not approved for production scoring**. Set a selected local model only after evaluation. A model/schema failure never creates a scored card. The current API invokes the local CLI synchronously as an integration bridge; Dev 3's durable MongoDB queue, retry, event stream, rubric administration, and production worker deployment remain pending.

The screen shows cited text and PDF page/region metadata. A clickable original-page image depends on Dev 1's private-file endpoint and Dev 4's shared evidence viewer. Dev 1 also owns mobile PDF upload, translation/TTS, entrepreneur follow-up answers, and feedback delivery. Dev 3 owns published rubric versions, cohorts, trade administration, and the queue. Dev 2 still must connect local-market sources, similarity/duplicates, rankings, imports, route suggestions, cohort views, and remaining P1 tools; none is represented as complete by this first slice.
