# Centre EDP scoring plan · provisional v1

The assessor uploads an original two-page English digital business idea PDF, reviews the extracted answers, requests an evidence-linked assessment, and makes the final decision. The EDP Idea Brief and the English Business Idea form-fillup family are supported. The latter locates printed question anchors in the left column and pairs each with its right-column answer, so varying answer lengths can shift rows without corrupting the mapping. Other layouts, scans, handwriting and languages stay pending until extraction is validated.

For the judge demo, the evaluation desk also offers “Evaluate PDF” in development/test mode. An authenticated centre staff member chooses the two-page PDF and sees the same evidence-linked scorecard beside a browser-local original, without entering applicant details first. This path sends only locally redacted answer evidence to Groq; it does not store the PDF, create an applicant/submission/consent record, or allow a saved human decision. It is disabled in production. The stored-plan path below still requires active recorded processing consent. A demo preview is not evidence that an applicant granted consent for ongoing production processing.

## Flow

1. Keep the original PDF private in the existing centre intake. Locally map recognized printed questions to the approved `CentreExtractedInput` fields using question text, column boundaries and source boxes. The form-fillup puts location last and splits customer demographics from customer segment; only the segment answer is used for scoring, while demographic boxes are excluded. Blank answers are `missing`, omitted questions are `not_asked`, and ambiguous/unsupported source mapping is rejected. No answer is fabricated.
2. Redact known applicant name, phone, email and IDs locally. Omit exact address from the model evidence. Validate the same contract and citation IDs used by the current scorer. A failed redaction or extraction produces a visible pending/error state and no numeric score.
3. Only the server can request Groq scoring, after a centre-scope check and an active processing-consent check. English centre imports can record that consent by attaching playable audio of the applicant's agreement to the current notice; staff attest to the words, since the server validates audio format/duration but does not transcribe it. Send only redacted answer evidence for the eight applicable domains. Keep the API key on the worker, use a fixed Groq endpoint/model with strict JSON output, bounded response and timeouts, and do not log prompts or originals.
4. Run the model twice. The provisional 1–5 domain anchors and weights are the PRD §13 rubric: clarity 10, customer need 15, market potential 15, feasibility 15, competition 10, differentiation 10, financial logic 15, readiness 10. Missing domains remain unscored. Every rating must cite 1–3 allowed answer IDs; reject missing, duplicated or unsupported citations. Flag low confidence or runs differing by more than one point.
5. Compute completeness, coverage, weighted potential, band, quadrant and suggested pathway in code using the existing scorer. The model cannot set totals or decide for the assessor. A human reviews quotes and decides; an override requires a reason.

## Release checks and limits

- Synthetic extraction tests cover ten rows, bounding boxes, redaction and refusal on ambiguous layouts. Access tests cover sibling-centre denial, absent consent and valid same-centre evaluation. Scorer tests cover missing evidence, malformed model output and two-run disagreement.
- Run the supplied sample end to end and report its actual domain results, elapsed time and model. One sample is a smoke test, not a claim of scoring accuracy or language/format parity. Official weights and ground-truth ratings are still needed before production quality approval.
- Live sample passes on 2026-10-17 returned 80, 83 and 80 potential, with 100 completeness and 90 domain coverage, using GPT-OSS 120B through Groq. The saved private report is `datasets/reports/edp-sample-groq-2026-10-17.json` (ignored). Readiness remained unscored because the form had no cited skills/experience. The saved two-call run used 2,322 input and 1,518 output tokens in about four seconds of adapter time. The three-point variation across passes and unverified financial numbers require calibration and human review; the card flags the financial check gap.
- A separate 2026-10-17 no-details demo-preview smoke pass extracted all ten answers from the same sample and returned 77 potential at 90% domain coverage. This additional variation reinforces that the provisional model score is a review aid, not calibrated ground truth.
- The user-selected `Business_Idea_Example_1_English.pdf` is a different 29,990-byte English form-fillup, not the 15,327-byte EDP Scenario 1. Its second verified layout extracted ten redacted answers with page boxes and passed local contract validation. A 2026-10-18 local guarded score returned 61, and the authenticated dashboard-proxy upload returned 62 potential, both at 100 completeness and 90 domain coverage. The financial-verification flag now cites the price/revenue evidence in whichever layout was used. These are smoke results, not official accuracy labels.
- The 42,442-byte `Business_Idea_Example_5_English.pdf` shifted later rows upward, exposing the fixed-coordinate failure. Anchor-based extraction mapped its ten answers and withheld one sentence containing possible exact-location detail in competition evidence. It returned 63 in a local guarded pass and 58 through the authenticated dashboard route, at 100 completeness and 90 coverage. All six local English form-fillup examples passed extraction/schema/redaction checks; examples with blank or omitted questions kept those fields unscored. This remains a narrow English family, not generic A-09 completion.
- Groq is the user's requested exception to the current D-24 local-only architecture, scoped to centre EDP scoring. It incurs hosted inference cost and sends redacted business evidence outside the local runtime. General ingestion, translation, speech and other providers stay local. Consent and organiser approval for hosted processing must be confirmed before live organiser records are sent. No fallback may fabricate an assessment.
